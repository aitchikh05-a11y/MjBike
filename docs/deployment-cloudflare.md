# Deploying to Cloudflare Pages

The site is a static Vite build plus Pages Functions in `functions/api` (mounted at `/api`).

## 1. One-time setup

```bash
npm install -g wrangler   # or use npx
wrangler login
```

Create the project (first deploy creates it automatically):

```bash
npm run build
npx wrangler pages deploy dist --project-name mj-bike-tangier
```

Git-connected alternative: connect the repository in the Cloudflare dashboard with

| Setting | Value |
| --- | --- |
| Framework preset | Vite |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Node version | 20 or later |

Functions are detected automatically from `functions/`.

## 2. Environment variables

Add these in **Pages → mj-bike-tangier → Settings → Environment variables** for both
Production and Preview:

Browser: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_SITE_URL`
Server: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `RESEND_API_KEY`, `EMAIL_FROM`, `ADMIN_EMAIL`, `SITE_URL`,
and optionally `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`.

Redeploy after changing any variable — Vite inlines `VITE_*` at build time.

Verify the API configuration:

```bash
curl -s https://mjbiketangier.com/api/health
# {"ok":true,"supabase":true,"email":true,"whatsapp":false,...}
```

## 3. DNS and custom domain

1. Add the domain to Cloudflare (nameservers updated at the registrar).
2. Pages → Custom domains → **Set up a domain** → `mjbiketangier.com` and `www.mjbiketangier.com`.
3. Cloudflare creates the proxied records automatically:
   - apex `CNAME`/flattened → `mj-bike-tangier.pages.dev`
   - `www` `CNAME` → `mj-bike-tangier.pages.dev`
4. Add a redirect rule so `www` → apex (or the inverse) with a 301, keeping the path:
   - **Rules → Redirect Rules → Create rule**
   - When: `http.host eq "www.mjbiketangier.com"`
   - Then: dynamic redirect to `concat("https://mjbiketangier.com", http.request.uri.path)`, status 301.
5. SSL/TLS: **Full (strict)**, Always Use HTTPS on, Automatic HTTPS Rewrites on, minimum TLS 1.2.

## 4. SPA routing

`public/_redirects` should contain a fallback so deep links resolve:

```
/*  /index.html  200
```

Cloudflare Pages serves existing assets first, so `/api/*` and hashed assets are unaffected.

## 5. Security headers (CSP)

Create `public/_headers`:

```
/*
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  X-Frame-Options: DENY
  Permissions-Policy: geolocation=(), microphone=(), camera=()
  Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
  Content-Security-Policy: default-src 'self'; base-uri 'self'; object-src 'none'; frame-ancestors 'none'; img-src 'self' data: blob: https://*.supabase.co; media-src 'self' https://*.supabase.co; font-src 'self' https://fonts.gstatic.com; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; script-src 'self'; connect-src 'self' https://*.supabase.co https://api.resend.com; form-action 'self'; upgrade-insecure-requests

/api/*
  Cache-Control: no-store
```

Notes:

- `'unsafe-inline'` for styles is required by the Google Fonts stylesheet and inline style
  attributes generated by Recharts. Scripts stay strict (`'self'`).
- If you later add a payment provider or another API, extend `connect-src` explicitly.
- Cloudflare may inject its analytics beacon; add `https://static.cloudflareinsights.com` to
  `script-src` if you enable Web Analytics.

## 6. Caching

| Path | Cache policy |
| --- | --- |
| `/assets/*` (hashed) | `public, max-age=31536000, immutable` (Pages default) |
| `/images/*` | `public, max-age=604800` (long cache; rename files when replacing) |
| `/index.html` | `no-cache` so deployments reach users immediately |
| `/api/*` | `no-store` |

Add to `public/_headers`:

```
/assets/*
  Cache-Control: public, max-age=31536000, immutable

/index.html
  Cache-Control: no-cache

/api/*
  Cache-Control: no-store
```

Purge the Cloudflare cache after changing `_headers`, `_redirects` or the `images/` folder.

## 7. Supabase CORS and URLs

- Supabase → Authentication → URL configuration:
  - Site URL: `https://mjbiketangier.com`
  - Additional redirect URLs: `https://mjbiketangier.com/admin/update-password`,
    `https://preview.mj-bike-tangier.pages.dev/admin/update-password`, `http://localhost:5173/admin/update-password`
- The API validates `Origin` against `SITE_URL` plus localhost and `*.pages.dev` previews
  (`functions/api/[[route]].ts`).

## 8. Backups and rollback

- **Code rollback:** Pages → Deployments → choose a previous successful deployment →
  **Rollback to this deployment**. Preview deployments are equally reversible.
- **Database rollback:** migrations are forward-only. Before a risky migration:
  `supabase db dump -f backup-$(date +%F).sql`, and test on a branch database.
- **Seed content:** re-running `supabase/seed.sql` replaces catalogue rows (services, offers,
  gallery, bicycles, availability rules, settings) and leaves reservations untouched.
- **Storage:** media lives in the `media` bucket; enable Supabase PITR or schedule backups
  before bulk uploads.

## 9. Post-deploy verification

```bash
curl -I https://mjbiketangier.com/en/                 # 200, HSTS, CSP
curl -I https://mjbiketangier.com/fr/location-velos/  # 200
curl -I https://mjbiketangier.com/ar/tajir-darajat/   # 200
curl -s https://mjbiketangier.com/api/health
```

Then run through the reservation flow once in production and confirm:

- a pending reservation appears in `/admin/reservations`,
- the customer receives the "request received" email (not a confirmation),
- the admin notification arrives,
- confirming sends the confirmation email and writes history/audit rows.
